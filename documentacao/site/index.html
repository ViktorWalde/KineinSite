PROJETO ABERTO À COLABORAÇÃO

O site também é um projeto.

Aqui estão as peças que existem hoje e os próximos trabalhos que podemos verificar. Este roteiro trata do site; o estado da IDE está descrito na página inicial.

01 / NESTE SITE

O que existe hoje.

Página inicial com capturas e demonstrações da IDE, notas de atualização, percursos de C++, Rust e Python e um exercício de C. Três temas e três cores de destaque. Antes de publicar, o build confere tipos, estilo, contraste das cores, HTML, links internos e a política de segurança de cada página.

O estudo de telemetria pode ser executado pelo terminal ou como continuação do projeto C++. Os tutoriais mostram a versão e o ambiente usados na reprodução dos passos.

02 / COMO FUNCIONA

Páginas estáticas e conteúdo verificado.

Astro gera as páginas estáticas, e o GitHub Pages entrega os arquivos. O site funciona sem backend próprio ou banco de dados. As preferências de tema ficam no navegador. Estudos de linguagem são escritos em Markdown e só geram página pública quando estão marcados como verificados.

Para trabalhar no repositório, use Node.js 24, npm ci enpm run dev. Antes de propor uma mudança, executenpm run build:pages. A documentação de arquitetura no repositório descreve coleções, rotas e publicação em detalhes.

03 / ROADMAP DO SITE

Próximos trabalhos, com critério de conclusão.

  1. Atualizar o Guia para a 0.4

    Após a release, reproduzir os oito capítulos na nova versão, ajustar telas e passos e publicar somente os fluxos conferidos.

  2. Ampliar os estudos verificados

    Acrescentar validação de entradas e testes em C++ depois de executar os exemplos e conferir cada resultado.

  3. Reativar a validação automática

    Voltar a rodar o build em cada pull request assim que a conta puder iniciar jobs do GitHub Actions.

  4. Conferir os links externos

    O build confere os links internos; os externos essenciais são revistos a cada mudança de conteúdo.

Recursos ainda não validados da IDE não têm data de publicação como guia. O roadmap detalhado registra as condições de cada entrega.

04 / CONTRIBUIR

Correções e estudos são bem-vindos.

Explique o problema, mostre o resultado esperado e indique como verificou a mudança. Para um estudo, registre fontes, ferramentas e resultado da execução. A publicação fica com os mantenedores.
